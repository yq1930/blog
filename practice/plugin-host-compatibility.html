插件能安装却不能保存：宿主接口与版本兼容 ​

插件安装成功，设置页也能打开，点保存后却没有真正生效。这里至少有三件不同的事：包管理器接受依赖范围、宿主提供对应能力、宿主接受并持久化修改。

本文取材于一个桌面主题扩展在 2026 年 9—10 月的接口迁移，核对日期为 2026-10-23。只讨论通用插件工程，不复制项目配置、素材或宿主内部实现。

先把三种版本分开 ​

版本表达什么不能代替什么
插件版本这次插件发布的身份宿主版本
开发依赖版本编译时使用的类型与工具实际用户环境
宿主兼容范围声明允许协作的宿主版本真实兼容验证

近期修复将开发依赖对齐到新的宿主 SDK，同时放宽了原先过窄的兼容声明。但仅改范围不能自动完成接口迁移；实际代码也调整了注入服务、配置命名空间和宿主侧注册方式。

peerDependencies 用于表达与宿主或其他包的兼容关系，不能把安装检查通过当成运行验收。npm package.json

接口名称改变，数据责任也可能改变 ​

这次迁移从旧的设置绑定接口转向宿主提供的配置表单能力。客户端按命名空间取表单，订阅权威快照，再根据当前状态判断是否能编辑和保存。

应把这条链作为一个整体核对：

text
宿主注册配置定义
       ↓
客户端取得对应命名空间
       ↓
加载状态与可写能力
       ↓
草稿 + 基线版本 → 提交修改
       ↓
宿主接受结果 + 权威快照 → 确认保存

只替换一个方法名，可能留下另一端未注册、命名空间不一致或只读连接的问题。当前界面分别显示加载中、连接能力不足、保存结果未确认与冲突，而不是一律显示空设置。

Promise 完成不等于宿主接受 ​

近期修复显式检查修改操作的接受结果，然后再次读取宿主快照，确认它处于可确认状态且值与提交目标相符，才更新页面基线。

通用教学伪代码可以这样表达：

js
const accepted = await form.write(changes, baseRevision);
if (!accepted) throw new Error('WRITE_REJECTED');

const current = form.snapshot();
if (!current.authoritative || !sameValues(current.value, submitted)) {
  throw new Error('WRITE_UNCONFIRMED');
}

这里的 API 名称是示意。重点是把“调用结束”“写入被接受”“确认当前值”分开，而不是建议读者复制一个宿主专用函数。

当前设置页还区分草稿与已保存基线。其他窗口更新时，没有本地修改可以同步；有未保存草稿则保留草稿并提示冲突。重新加载应由用户明确选择。

恢复默认值不一定是写回一组默认常量 ​

在分层配置里，用户值可能覆盖宿主或插件默认值。当前重置操作删除用户覆盖键，再确认这些键确实不再存在，而不是只比较界面显示是否等于默认值。

否则今天把默认值复制进用户设置，明天宿主更新默认值后，用户仍会被旧覆盖值锁住。

这是配置语义问题。只有宿主确实采用继承与覆盖模型时，删除覆盖才有这种含义；不能推广到所有设置系统。

预发布版本范围尤其容易误读 ​

默认的 node-semver 匹配会限制预发布版本。一个范围显式包含某个版本的 rc，并不表示后续小版本的所有 rc 都会匹配。node-semver 预发布规则

以下是独立合成示例，统一使用范围 >=1.4.0-rc.1 <2.0.0。结果已在本地用 node-semver 核对，未加载目标宿主：

被判断版本默认匹配结果
1.4.0-rc.2匹配
1.5.0-rc.1不匹配
1.5.0匹配

因此，源码里“放宽了范围”与“覆盖所有桌面预发布运行时”不能画等号。建议用实际发布过的目标版本逐个测试；如果宿主采用特殊匹配参数，也要明确记录，不能默认它启用了预发布兼容选项。

检查消费者真正加载的产物 ​

当前扩展将宿主入口与客户端入口分别构建，并把部分宿主共享依赖留为 external；包入口指向生成后的文件。只改源代码、不更新实际入口产物，会出现“仓库看起来修好了，用户加载的还是旧代码”。

发布前应核对源代码、类型检查、构建结果、导出路径和包内容是否一致，并确认运行时由谁提供 external 依赖。能在开发目录运行，不等于安装包包含了全部必要文件。

这里总结的是现有构建模式，没有实际执行这次扩展的安装或桌面兼容矩阵，也没有重新分发其素材。

建议验证矩阵 ​

  • [ ] 最低支持版本、常用稳定版本与目标预发布版本分别加载。
  • [ ] 宿主和客户端能力缺失时，给出可理解的不可用状态。
  • [ ] 修改被拒绝或返回不一致快照时，不显示保存成功。
  • [ ] 两窗口同时编辑，失败者仍保留草稿。
  • [ ] 重置后用户覆盖层消失，而不只是视觉值相同。
  • [ ] 实际打包产物中的入口、依赖与源码版本一致。

延伸阅读：编辑会话与本地草稿、构建工具选型。
