打印为什么多一张空白页：从屏幕布局到纸张布局 ​

页面预览只有一张凭证，打印却多一张空白页。先不要缩小字号或随意调整缩放比例，应该检查实际打印文档里有哪些盒子占用了空间。

本文基于一个 PC 后台近期两组打印修复的静态分析，核对日期为 2026-10-23。原项目使用 Print.js，包含单条与批量打印。本文没有执行真实打印机验收。

屏幕正确，不代表打印文档正确 ​

打印库可能在 iframe 中创建文档，把页面节点和计算后的样式复制进去。外层页面的样式、默认边距和组件 scoped 样式，不一定以预期方式出现在打印文档里。

Print.js 提供 style、css、scanStyles 和 targetStyles 等参数；排查时应看实际传给打印文档的规则，而不是只看原页面的 CSS。Print.js 文档

本次修复主要做了三件事：

  1. 清理打印文档中 html、body 的默认边距。
  2. 去掉预览用途的固定高度与底部留白。
  3. 只在相邻凭证之间强制分页。

一张空白页可能来自多个小尺寸相加 ​

尺寸来源常见误判
容器固定高度正文短就一定不会溢出
页面底部留白空白没有内容，所以不占打印空间
内外边距与边框只测表格正文高度即可
浏览器页边距A4 尺寸就是内容可用尺寸
打印页眉页脚预览里没有，就不会影响打印

近期凭证修复移除了内容区固定高度；明细修复则清理了打印容器和表格的底部空间。它们处理的是不同来源的占位，不能简单归纳为“把 height 改成 auto”。

建议先把可打印高度视为一个预算：纸张高度减去实际页边距及其他占用，再核对正文、标题、表格和签名区的总高度。具体值由目标浏览器和打印设置决定。

分页只发生在两份内容之间 ​

如果每个块都无条件设置强制分页，最后一个块也会留下多余的分页要求。是否呈现为空白页还受浏览器与结构影响，不能依赖它自动忽略。

以下是通用教学规则，假设打印根节点只包含若干 .sheet，没有额外尾部兄弟节点：

css
@media print {
  html, body {
    margin: 0;
    padding: 0;
  }

  .sheet {
    height: auto;
    margin-bottom: 0;
  }

  .sheet:not(:last-child) {
    break-after: page;
  }
}

break-after: page 明确要求在当前盒子之后分页。如果打印容器还混有按钮、状态节点或其他兄弟元素，:last-child 的含义就会改变；应先整理结构，或为最后一份内容显式标记。MDN break-after

项目通过打印专用样式覆盖被复制的计算样式，部分规则使用 !important。这是针对该复制链路的局部处理，不应把 !important 当成所有打印问题的通用解法。

缩放比例是验收结果，不是万能常量 ​

其中一类明细有固定行数和较宽表格，当前实现增加缩放以适应目标纸张。这个数值与行高、字体、列宽和打印设置相关，不能直接推广到另一张报表。

另外，maxWidth 参数以像素表达，纸张布局常使用毫米，浏览器打印对话框还可能再次缩放。必须明确是哪一层在缩放，避免多层叠加后文字过小或二维码难以识别。

内容明显超过一页时，应设计表头重复、行拆分和页码，而不是不断把整页压小。是否允许某一行跨页，也要按内容决定。

单条修好后，还要检查批量入口 ​

这次代码同时修复了单条和批量版本。因为它们各自配置打印参数，只改一个入口会留下“列表批量打印仍有空页”的问题。

建议下一步把公共打印规则集中起来，只把模板差异作为参数。不过，近期修复仍是同步调整多个组件，不能写成已经完成统一打印模块。

建议验证矩阵 ​

维度至少检查
数量单份、两份、多份，以及空数据
内容最短、刚好一页、长名称换行、超过一页
入口单条打印与批量打印
设置目标纸型、页边距、缩放、页眉页脚
输出PDF 预览页数与实际打印结果

先确认最后一页是否有真实溢出内容，再判断是不是纯空白。验收同时看页数、裁切、文字大小和内容完整性，不能只以“少了一页”为成功标准。
