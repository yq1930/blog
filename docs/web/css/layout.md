# 响应式布局与容器

响应式不是为几个设备型号写补丁，而是让内容在可用空间变化时仍保持层级、可读性和可触达性。先设计容器与布局规则，再添加少量真正需要的断点。

## 内容容器决定阅读节奏

正文不应无限拉宽。使用最大宽度和左右内边距，让大屏阅读保持合适的行长，小屏也不会贴边。

```css
.content-shell {
  width: min(100% - 32px, 72rem);
  margin-inline: auto;
}

.article-body {
  max-width: 46rem;
}
```

`min()` 让容器在小屏保留边距、在大屏停止增长。正文与页面容器分开设置，列表和卡片可以更宽，长文仍然易读。

## Grid 管结构，Flex 管一维对齐

网格适合卡片、主栏/侧栏等二维布局；弹性布局适合按钮组、导航和标题行。不要强迫其中一种解决所有问题。

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  gap: 1rem;
}

.actions {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
  align-items: center;
}
```

`auto-fit` 和 `minmax()` 让卡片在空间不足时自动换行，许多场景无需专门写“平板三列、手机一列”的硬编码断点。

## 断点服务于布局失效点

当导航挤不下、双栏正文过窄或操作按钮难以点击时，才需要媒体查询。选择项目真实出现问题的宽度，而不是背诵设备名称。

```css
@media (max-width: 48rem) {
  .page-layout {
    grid-template-columns: 1fr;
  }

  .page-aside {
    order: -1;
  }
}
```

## 小屏验收不只看“没有横向滚动”

- 文字、表格和代码块是否仍可理解；宽表格应允许容器横向滚动，不要压缩到不可读。
- 主要操作的触控区域是否足够大，彼此间是否留有间距。
- 长标题、异常长度的标签和空数据是否会撑破布局。
- 键盘焦点与跳过导航链接是否仍能看到。

布局的目标是帮助内容被读取和操作。视觉对齐只是结果，不是唯一标准。
